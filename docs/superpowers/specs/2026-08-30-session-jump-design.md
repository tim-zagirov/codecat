# Переход к сессии, которая ждёт ответа — дизайн-спецификация

Дата: 2026-08-30
Статус: утверждена пользователем
Предшествующий спек: `2026-08-28-codecat-design.md` (CodeCat MVP, влит в master)

## Задача

Когда агент ждёт ответа, пользователь должен попадать к нему одним кликом, а не искать нужное окно среди десятка открытых. Клик по строке сессии в панели деталей переключает пользователя туда, где эта сессия живёт.

## Что выяснено до проектирования

Проверено на реальной машине через `CGWindowListCopyWindowInfo`:

- У десктопного приложения Claude **7 окон, и все принадлежат одному процессу** (главному процессу приложения). Отдельные сессии — это дочерние процессы `claude`, и **собственных окон у них нет**. Соответствия «сессия → окно» на уровне системы не существует.
- Заголовки окон читаются пустыми: `kCGWindowName` требует разрешения на Запись экрана.

Отсюда следует граница возможного: точное наведение реально для терминальных сессий (через TTY), а для десктопного Claude максимум честного — вывести приложение вперёд. Попытки угадывать окна Claude по заголовкам в этот дизайн не входят: угадывание будет промахиваться, а цена — тяжёлое разрешение.

## Сбор данных о маршруте

`codecat-hook` запускается дочерним процессом от `claude`, поэтому знает то, чего нет в payload'е хука. На каждом событии он добавляет в пересылаемый JSON три поля:

- `host_pid` — PID приложения-владельца (первый предок, исполняемый файл которого лежит внутри `.app`-бандла);
- `host_bundle_path` — путь к этому бандлу;
- `tty` — имя терминального устройства процесса `claude`, либо отсутствует.

Обход предков и чтение TTY делаются через `sysctl(KERN_PROC_PID)`: это несколько системных вызовов без запуска подпроцессов. Требование «хук никогда не тормозит Claude Code» остаётся в силе.

Если разбор входного JSON не удался, хук пересылает полученные байты дословно, как сейчас, и ничего не добавляет. Обогащение payload'а не имеет права стать причиной потери события.

Данные собираются на каждом событии, а не только на `SessionStart`: это дёшево и самовосстанавливается, если CodeCat запустили позже сессии.

## Модель

`HookEvent` получает три новых опциональных поля. `Session` — их же, чтобы маршрут пережил обновления состояния. Все опциональные: сессия, обнаруженная вотчером транскриптов, маршрута не имеет.

## SessionRouter — чистая логика

Новый тип в `CodeCatCore`. На входе данные сессии, на выходе решение:

```swift
public enum JumpRoute: Equatable {
    case terminalTab(bundlePath: String, tty: String)
    case application(pid: pid_t, bundlePath: String)
    case unavailable(reason: UnavailableReason)
}

public enum UnavailableReason: Equatable {
    case noHostRecorded   // сессия появилась из транскриптов, хук её не видел
    case hostGone         // приложение-владелец больше не запущено
}
```

Правила, по убыванию точности:

1. Известен TTY **и** бандл-владелец опознан как терминал с поддержкой выбора вкладки (Terminal.app, iTerm2) → `terminalTab`.
2. Известен бандл-владелец → `application`.
3. Иначе → `unavailable`.

Опознание терминалов — по bundle identifier, список задаётся константой. Функция чистая, зависимостей от системы нет, тестируется на фиксированных входах.

## Исполнение маршрута — слой приложения

Исполнитель прячется за узким протоколом, который в тестах подменяется — так же, как `runner` в `LidSleepController`:

```swift
public protocol JumpExecuting {
    func perform(_ route: JumpRoute) -> JumpOutcome
}

public enum JumpOutcome: Equatable {
    case switchedToTab              // попали точно во вкладку
    case switchedToApplication      // вывели приложение вперёд
    case automationDenied           // пользователь отклонил разрешение на автоматизацию
    case tabNotFound                // вкладку закрыли
    case hostGone                   // процесса приложения больше нет
    case failed(String)             // прочая ошибка, текст для сообщения
}
```

`automationDenied` и `tabNotFound` — не терминальные исходы: исполнитель сам делает запасную попытку вывести приложение вперёд и сообщает, что точного попадания не вышло.

Реальная реализация:

- `terminalTab` — AppleScript, выбирающий вкладку с совпадающим TTY и выводящий её окно вперёд. При первом использовании macOS один раз спросит разрешение на автоматизацию конкретного терминала. Это лёгкое разрешение, не Accessibility и не Запись экрана.
- `application` — `NSRunningApplication(processIdentifier:)` и `activate()`. Разрешений не требует.

Путь к бандлу и TTY подставляются в AppleScript только через экранирование, тем же способом, что уже применён для пути установочного скрипта в `LidHelperInstall.appleScript(forScriptAt:)`.

## Что видит пользователь

Строки сессий в панели деталей становятся кликабельными:

- Есть маршрут: курсор-указатель, подсветка при наведении. Клик переключает и закрывает панель.
- Маршрута нет: подсветки нет, под строкой мелкая подпись «переход недоступен — сессия запущена до CodeCat». Мёртвых кликов без объяснения быть не должно.

Клик по самому котику поведения не меняет — по-прежнему открывает панель.

## Обработка ошибок

- Пользователь отклонил запрос на автоматизацию терминала → показываем сообщение по-русски, что для перехода к вкладке нужно разрешение, и выполняем запасной вариант: выводим приложение вперёд.
- AppleScript вернул ошибку или нужная вкладка не найдена (её закрыли) → запасной вариант с выводом приложения вперёд, сообщение о том, что вкладку найти не удалось.
- Процесса приложения больше нет → сообщение, что сессия закрыта; строка остаётся до штатного истечения.
- Все сообщения — по-русски, все исходы докладываются: молчаливых отказов нет.

Исполнитель не блокирует главный поток: AppleScript выполняется вне его, результат применяется на главной очереди.

## Тестирование

- `SessionRouter`: выбор маршрута для каждого сочетания входов — терминал с TTY, терминал без TTY, не-терминальный бандл, полностью неизвестная сессия.
- Обход предков и определение бандла-владельца: логика отделена от системных вызовов через инжектируемого поставщика сведений о процессах, тестируется на смоделированном дереве процессов.
- Экранирование TTY и пути в AppleScript: на строках со пробелами, кавычками и обратными слэшами.
- Разбор нового payload'а хука: наличие и отсутствие новых полей, битый JSON.
- Обработка исходов перехода: каждый исход исполнителя приводит к ожидаемому сообщению, через подменённый `JumpExecuting`.

Слой AppKit (реальная активация приложения и запуск AppleScript) юнит-тестами не покрывается — это установившаяся граница проекта; проверяется вручную.

## За скобками

- Наведение на конкретное окно десктопного Claude — невозможно по причинам выше.
- Глобальная горячая клавиша для перехода к ждущему агенту.
- Переход по клику на самого котика.
- Поддержка терминалов помимо Terminal.app и iTerm2 — для них работает вывод приложения вперёд.
