# Облики котика: подключение бесплатных наборов с переключением — дизайн-спецификация

Дата: 2026-08-30
Статус: утверждена пользователем
Предшествующие спеки: `2026-08-28-codecat-design.md` (MVP), `2026-08-30-session-jump-design.md` (переход к сессии)

## Задача

Дать пользователю выбор внешнего вида маскота: кроме нынешнего нарисованного кота — все бесплатные наборы спрайтов, которые прошли проверку лицензий. Переключение в панели деталей, живыми превью. Нарисованный кот остаётся по умолчанию.

## Что проверено до проектирования

Лицензии перечитаны на страницах источников (не по отчёту `docs/cat-assets-research.md`), файлы скачаны с разрешения пользователя и рассмотрены:

| Набор | Что написано на странице | Проверено в файлах |
|---|---|---|
| [LuizMelo — Pet Cats Pack](https://luizmelo.itch.io/pet-cat-pack) | «This package can be used freely and commercially — CC0», asset license: Creative Commons Zero v1.0 | В архиве лежит `License.txt`: «This pack — Pet Cats Pack Asset Pack is Creative Commons Zero (CC-0). Can be used in commercial and non-commercial projects.» 6 котов, кадр 50×50 px, кот внутри кадра ~19×14 px |
| [Elthen — 2D Pixel Art Cat Sprites](https://elthen.itch.io/2d-pixel-art-cat-sprites) | Формальной лицензии на странице нет: «Feel free to use the sprites in commercial/non-commercial projects!». Условия — на [Patreon](https://www.patreon.com/posts/27430241): коммерческое использование можно; нельзя перепродавать и раздавать сами ассеты; нельзя в blockchain/NFT/p2e проектах; кредиты не обязательны | Один лист 256×320, сетка 8×10 кадров по 32×32, кот бело-серый |
| [mxmaze — 16-Bit Kitty (FREE)](https://mxmaze.itch.io/16-bit-kitty-free) | Asset license: Creative Commons Attribution v4.0 International; автор подтверждает в комментариях. **Атрибуция обязательна** | Один лист 48×48, сетка 3×3 по 16×16, кот коричневый |

Отвергнуто: [OpenGameArt Cat sprites](https://opengameart.org/content/cat-sprites) — CC0, но только walk/run, ни одного нужного состояния; LottieFiles и IconScout — страницы лицензий недоступны (HTTP 403), условия подтвердить не удалось.

Что видно только из самих файлов и меняет дизайн:

- **У `Cat-3` из набора LuizMelo нет анимации `Itch`** — единственного кандидата на состояние «проблема». Остальные пять котов её имеют. Значит таблица соответствий строится **на каждый облик**, а не на набор.
- **Кот Elthen бело-серый, почти контурный.** На светлом рабочем столе он читается заметно хуже плотного оранжевого. Это не блокирует, но объясняет, почему нарисованный кот остаётся по умолчанию.
- **У mxmaze всего 9 кадров**, «ждёт тебя» и «проблема» закрывать нечем.
- **Кот `Cat-1` у LuizMelo рыжий** — единственный из всех скачанных, кто попадает в тёплую палитру нынешнего кота.

## Решения, принятые с пользователем

1. Подключаем все три набора. Обликов девять: нарисованный + шесть котов LuizMelo + Elthen + mxmaze.
2. В состояниях, которых в наборе нет, показываем **ближайшую анимацию того же набора**. Стили не смешиваются никогда: нарисованный кот не подставляется в пиксельный облик и наоборот. Смысловое различие несёт бейдж, который уже есть (красный пульсирующий, когда агент ждёт).
3. Переключение — в панели деталей, рядом живых превью. Там же строка «Об ассетах» с авторами и лицензиями.

## Модель — `CodeCatCore`

Чистая, без AppKit и без обращений к файловой системе, поэтому тестируется целиком.

```swift
/// Один кадр: файл спрайт-листа и позиция кадра в нём.
public struct SpriteFrame: Equatable, Sendable {
    public let sheet: String   // имя файла в каталоге облика
    public let index: Int      // порядковый номер кадра в листе, слева направо, сверху вниз
}

/// Зацикленная анимация одного состояния.
public struct SpriteAnimation: Equatable, Sendable {
    public let frames: [SpriteFrame]
    public let framesPerSecond: Double
}

public struct MascotSkin: Equatable, Sendable, Identifiable {
    public let id: String              // хранится в UserDefaults, менять нельзя
    public let name: String            // подпись в интерфейсе, по-русски
    public let author: String
    public let license: SkinLicense
    public let sourceURL: String
    /// Каталог с листами внутри ресурсов; nil у нарисованного кота.
    public let directory: String?
    /// Кадр 50×50 у LuizMelo, 32×32 у Elthen, 16×16 у mxmaze.
    public let frameSize: Int
    public let animations: [AggregateStatusKey: SpriteAnimation]
}

public enum SkinLicense: Equatable, Sendable {
    case cc0
    case ccBy4(attributionTo: String)
    case authorTerms(summary: String)  // Elthen: своими словами, со ссылкой на источник
    case builtIn                       // нарисованный кот
    public var requiresAttribution: Bool { if case .ccBy4 = self { return true }; return false }
}
```

Число столбцов в листе намеренно не объявляется: оно считается при загрузке из реальной ширины картинки (`ширина / frameSize`), а позиция кадра — как `x = (index % столбцы) * frameSize`, `y = (index / столбцы) * frameSize`. Объявленное число столбцов было бы четвёртым местом, где данные могут разойтись с файлом, и горизонтальные полосы LuizMelo разной длины пришлось бы описывать отдельно.

`AggregateStatusKey` — перечисление пяти состояний (`sleeping`, `working`, `waiting`, `done`, `problem`), плоское соответствие `AggregateStatus` без ассоциированных значений: анимация зависит от вида состояния, а не от числа сессий.

Реестр `MascotSkins.all: [MascotSkin]` перечисляет девять обликов; `MascotSkins.default` — нарисованный; `MascotSkins.skin(withID:)` возвращает нарисованного для неизвестного идентификатора, чтобы испорченный `UserDefaults` не оставил пользователя без маскота.

## Отрисовка — слой приложения

`SpriteSheetStore` загружает PNG из ресурсов один раз на файл и держит `CGImage` в памяти (все листы вместе — меньше 120 КБ).

`SpriteMascotView` рисует текущий кадр:

- Холст тот же `MascotLayout.canvasSize` (128 pt). Бейдж, перетаскивание и запас под анимации не меняются.
- **Целочисленный масштаб и отсутствие интерполяции.** `.interpolation(.none)` плюс масштаб, кратный единице, — иначе пиксельный кот превратится в мыло.
- **Масштаб считается на облик, а не на состояние.** Берётся объединяющая рамка непрозрачных пикселей по всем кадрам всех пяти анимаций облика; масштаб `S = max(1, floor(96 / max(ширина, высота)))`. Единый масштаб на облик обязателен: если считать его на состояние, кот будет менять размер при каждом переходе. 96 pt — та же область рисунка, что занимает нарисованный кот.
- **Кадрирование по объединяющей рамке анимации**, а не по кадру: внутри одной анимации движение сохраняется, а кот не прыгает по холсту.
- Смена кадров — `TimelineView(.periodic)` с периодом `1 / framesPerSecond`. fps держим в диапазоне 0.6–8: маскот висит на экране весь день, и частая перерисовка прозрачной панели стоит батареи.

`MascotView` выбирает между `CatView` (нарисованный) и `SpriteMascotView`. `OverlayPanel` показывает `MascotView` вместо `CatView`; больше в оверлее ничего не меняется.

## Ресурсы и сборка

Файлы уже скачаны и лежат в репозитории: `Resources/Skins/` (там же `CREDITS.md` и `fetch-assets.sh`, воспроизводящий скачивание). Первая задача реализации — перенести их в `Sources/CodeCatApp/Skins/<набор>/`: SwiftPM требует, чтобы ресурсы лежали внутри каталога таргета, а нынешний `Resources/` лежит в корне и копируется вручную Makefile'ом. В `Package.swift` таргет `CodeCatApp` получает `resources: [.copy("Skins")]`, доступ — через `Bundle.module`.

**`make app` должен дополнительно копировать `.build/release/CodeCat_CodeCatApp.bundle` в `Contents/Resources/`.** Без этого облики будут работать под `swift run` и молча ломаться в установленном приложении — ровно тот класс дефекта, который в этом проекте уже дважды ловился только запуском собранного бандла.

Рядом с ассетами кладётся `Sources/CodeCatApp/Skins/CREDITS.md` с автором, лицензией и ссылкой по каждому набору, и оригинальные файлы лицензий из архивов — как есть, без переписывания.

## Интерфейс

В панели деталей, ниже списка сессий и выше переключателей:

- Ряд превью, по одному на облик, ~36 pt, горизонтальная прокрутка при нехватке ширины. Каждое превью проигрывает анимацию состояния «ждёт тебя» — то, ради чего маскот и существует. Это девять анимаций одновременно, поэтому у превью fps ограничен четырьмя, и они существуют только пока панель открыта.
- Выбранный облик обведён рамкой. Тап переключает немедленно, панель не закрывается.
- Под рядом — строка «Об ассетах», раскрывающая список: имя набора, автор, лицензия, ссылка на источник. Для CC BY 4.0 это обязательство лицензии, для остальных — вежливость.

Выбор хранится в `UserDefaults` под ключом `mascotSkin`, по умолчанию `drawn`. Ничего не меняется само у тех, кто уже пользуется приложением.

## Обработка ошибок

- Лист не загрузился (файл потерян при сборке, битый PNG) → облик откатывается на нарисованного кота, в панели один раз показывается сообщение по-русски, что набор не удалось загрузить. Маскот не исчезает никогда.
- Неизвестный идентификатор в `UserDefaults` → нарисованный кот, молча: это не ошибка пользователя.
- Кадр вне листа (несовпадение объявленных кадров с реальным файлом) → ловится тестом на сборке, а не в рантайме (см. ниже).

## Тестирование

В `CodeCatCore`, на чистых данных:

- У каждого облика из реестра разрешены все пять состояний.
- Идентификаторы обликов уникальны и не меняются (тест фиксирует список — переименование сломает сохранённый выбор пользователя).
- Каждый облик, чья лицензия требует атрибуции, присутствует в списке credits; у каждого облика заполнены автор и ссылка на источник.
- Соответствие `AggregateStatus → AggregateStatusKey` покрывает все случаи, включая `.working(n)`/`.waiting(n)` с любым n.
- Ни у одной анимации нет пустого списка кадров и неположительного fps.

Тест на согласованность с файлами (в тестах приложения не выйдет — ресурсы лежат в таргете `CodeCatApp`, у которого тестов нет; значит лист проверяется тестом в `CodeCatCore` по пути к каталогу исходников, известному через `#filePath`): для каждого облика каждый объявленный файл существует, а максимальный объявленный индекс кадра меньше, чем `(ширина / frameSize) * (высота / frameSize)` реального PNG. Это тот тест, который ловит опечатку в таблице соответствий до запуска приложения.

Слой AppKit/SwiftUI (реальная отрисовка, превью, прокрутка) юнит-тестами не покрывается — установившаяся граница проекта. Проверяется рендером в PNG и запуском собранного бандла.

## За скобками

- Загрузка обликов пользователем со стороны.
- Покупные наборы (в отчёте есть вариант за $6) — решение по ним не принято и в эту работу не входит.
- Дорисовка недостающих состояний вручную в стиле каждого набора.
- Смена облика по расписанию, случайный облик, «кот дня».
