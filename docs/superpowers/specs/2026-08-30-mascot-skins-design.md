# Облики котика: подключение бесплатных наборов с переключением — дизайн-спецификация

Дата: 2026-08-30 (вычитана и уточнена в тот же день, см. «Что изменилось после вычитки»)
Статус: утверждена пользователем
Предшествующие спеки: `2026-08-28-codecat-design.md` (MVP), `2026-08-30-session-jump-design.md` (переход к сессии)

## Задача

Дать пользователю выбор внешнего вида маскота: все бесплатные наборы спрайтов, которые прошли проверку лицензий. Переключение в панели деталей, живыми превью. Нарисованный кот выбираться перестаёт — он остаётся в коде только как аварийная отрисовка на случай, если лист спрайтов не читается (см. «Что изменилось после вычитки», пункт 11).

Что видно только из самих файлов и меняет дизайн:

- **У `Cat-3` из набора LuizMelo нет анимации `Itch`** — единственного кандидата на состояние «проблема». Остальные пять котов её имеют. Значит таблица соответствий строится **на каждый облик**, а не на набор.
- **Коты LuizMelo — четвероногие, широкие и низкие** (рамка непрозрачных пикселей ~27×14 px), кот Elthen — 18×12, а кот mxmaze занимает **весь тайл 16×16**. Наивная нормировка «по большей стороне» развела бы их по высоте вдвое; см. раздел «Масштаб».
- **Кот Elthen бело-серый, почти контурный.** На светлом рабочем столе он читается заметно хуже плотного оранжевого. Это не блокирует выбор Elthen, но было одним из доводов за тёплый, плотный цвет облика по умолчанию (см. пункт 11 в «Что изменилось после вычитки»).
- **У mxmaze всего 9 кадров** — три позы по три кадра, причём **весь нижний ряд нарисован с закрытыми глазами**. Значит под «закончил» этот ряд отдавать нельзя: получилось бы «спит».
- **Анимация `Laying` у LuizMelo — переход «сел → лёг», а не петля.** Зацикленная, она заставила бы кота непрерывно вставать и ложиться, поэтому под сон идут однокадровые `Sleeping1`/`Sleeping2`.
- Цвета шести котов LuizMelo (по кадру `Idle`): `Cat-1` золотисто-рыжий, `Cat-2` чёрный, `Cat-3` сиамский (кремовый с тёмной мордой), `Cat-4` дымчатый серо-розовый, `Cat-5` белый, `Cat-6` серый полосатый. Отсюда подписи обликов.
- Нарисованный кот в положении сидя занимает **~87 pt по высоте и ~50 pt в корпусе** (по геометрии `CatView`: уши от y=−41, низ корпуса до y=+46). Это ориентир, к которому подгоняется масштаб спрайтов.

## Решения, принятые с пользователем

1. Подключаем все три набора. Выбираемых обликов восемь: шесть котов LuizMelo + Elthen + mxmaze. Нарисованный кот больше не в списке выбора.
2. В состояниях, которых в наборе нет, показываем **ближайшую анимацию того же набора**. Стили не смешиваются никогда: нарисованный кот не подставляется в пиксельный облик и наоборот. Смысловое различие несёт бейдж, который уже есть (красный пульсирующий, когда агент ждёт).
3. Переключение — в панели деталей, сеткой живых превью. Там же строка «Об ассетах» с авторами и лицензиями.

## Модель — `CodeCatCore`

Чистая, без AppKit и без обращений к файловой системе, поэтому тестируется целиком.

```swift
/// Один кадр: файл спрайт-листа и позиция кадра в нём.
public struct SpriteFrame: Equatable, Sendable {
    public let sheet: String   // имя файла в каталоге облика
    public let index: Int      // порядковый номер кадра в листе, слева направо, сверху вниз
}

/// Зацикленная анимация одного состояния.
public struct SpriteAnimation: Equatable, Sendable {
    public let frames: [SpriteFrame]
    public let framesPerSecond: Double
}

public struct MascotSkin: Equatable, Sendable, Identifiable {
    public let id: String              // хранится в UserDefaults, менять нельзя
    public let name: String            // подпись в интерфейсе, по-русски
    public let author: String
    public let license: SkinLicense
    public let sourceURL: String
    /// Каталог с листами внутри ресурсов.
    public let directory: String
    /// Кадр 50×50 у LuizMelo, 32×32 у Elthen, 16×16 у mxmaze.
    public let frameSize: Int
    public let animations: [AggregateStatusKey: SpriteAnimation]
}

public enum SkinLicense: Equatable, Sendable {
    case cc0
    case ccBy4(attributionTo: String)
    case authorTerms(summary: String)  // Elthen: своими словами, со ссылкой на источник
    public var requiresAttribution: Bool { if case .ccBy4 = self { return true }; return false }
}
```

Реестр — только эти восемь спрайтовых обликов. Нарисованный кот (`CatView`, в `CodeCatApp`) в него не входит: он больше не выбирается, а остаётся только аварийной отрисовкой на случай, если лист спрайтов не читается (см. «Обработка ошибок» и пункт 11 ниже).

Число столбцов в листе намеренно не объявляется: оно считается при загрузке из реальной ширины картинки (`ширина / frameSize`), а позиция кадра — как `x = (index % столбцы) * frameSize`, `y = (index / столбцы) * frameSize`. Объявленное число столбцов было бы четвёртым местом, где данные могут разойтись с файлом, и горизонтальные полосы LuizMelo разной длины пришлось бы описывать отдельно.

`AggregateStatusKey` — перечисление пяти состояний (`sleeping`, `working`, `waiting`, `done`, `problem`), плоское соответствие `AggregateStatus` без ассоциированных значений: анимация зависит от вида состояния, а не от числа сессий.

Реестр `MascotSkins.all: [MascotSkin]` перечисляет восемь обликов; `MascotSkins.default` — Рыжий (`luizmelo-cat-1`), самый близкий по духу к прежнему нарисованному коту из шести котов LuizMelo и единственный из них в тёплой палитре; `MascotSkins.skin(withID:)` возвращает облик по умолчанию для неизвестного идентификатора (включая сохранённый `"drawn"` — с этим сталкивается каждый, кто уже пользовался приложением), чтобы испорченный `UserDefaults` не оставил пользователя без маскота.

## Отрисовка — слой приложения

`SpriteSheetStore` загружает PNG из ресурсов один раз на файл и держит `CGImage` в памяти (все листы вместе — меньше 120 КБ).

`SpriteMascotView` рисует текущий кадр:

- Холст тот же `MascotLayout.canvasSize` (128 pt). Бейдж, перетаскивание и запас под анимации не меняются.
- **Целочисленный масштаб и отсутствие интерполяции.** `.interpolation(.none)` плюс масштаб, кратный единице, — иначе пиксельный кот превратится в мыло.

### Масштаб и кадрирование

Один прямоугольник на облик — **объединяющая рамка непрозрачных пикселей по всем кадрам всех пяти анимаций облика**, вычисленная при загрузке из самих пикселей. Он служит и рамкой кадрирования, и основой масштаба, и центрируется в холсте.

```
S = max(1, min(floor(64 / высота рамки), floor(120 / ширина рамки)))
```

- 64 pt — целевая высота маскота. Нарисованный кот сидя занимает ~87 pt, но коты LuizMelo четвероногие: подгонять их по высоте к сидящему коту значило бы растянуть их на 160 pt в ширину.
- 120 pt — предел ширины: холст 128 pt, немного слака остаётся на бейдж и края.

Что получается на реальных файлах: шесть котов LuizMelo не делят одну рамку тютелька в тютельку — у большинства (включая `Cat-1`) рамка 27×14 pt (108×56 pt на экране, S=4), но у `Cat-4` она 28×16, а у `Cat-5` — 27×16 (108–112×64 pt при том же S=4). Elthen — 90×60 (18×12, S=5), mxmaze — 64×64 (16×16, S=4). Высоты укладываются в 56–64 pt — облики читаются одного размера. **Наивное правило `floor(96 / max(ширина, высота))` этой проверки не проходит:** оно даёт LuizMelo 81×42, а mxmaze 96×96, то есть кот mxmaze вдвое выше кота LuizMelo, потому что его арт упирается в края тайла.

Рамка **одна на облик, а не на анимацию и не на кадр**. Это обязательно: у LuizMelo рамка спящего кота — 22×5, а работающего — 21×14, и покадровое кадрирование подбрасывало бы кота по холсту при каждой смене состояния. Внутри одной анимации движение при этом сохраняется полностью, потому что кадрируются все кадры одним и тем же прямоугольником.

### Тайминг

Смена кадров — `TimelineView(.periodic)` с периодом `1 / framesPerSecond`. fps держим в диапазоне 0.6–8: маскот висит на экране весь день, и частая перерисовка прозрачной панели стоит батареи.

`MascotView` рендерит `SpriteMascotView`, а на `CatView` (нарисованный) переходит только тогда, когда текущий облик не загрузился — выбором пользователя `CatView` больше не бывает. Бейдж (число сессий, красный пульсирующий в состоянии «ждёт») выносится из `CatView` в отдельный `MascotBadge` и накладывается обоими — у спрайтовых обликов он обязан выглядеть и располагаться ровно так же. `OverlayPanel` показывает `MascotView` вместо `CatView`; больше в оверлее ничего не меняется.

## Ресурсы и сборка

Файлы уже скачаны и лежат в репозитории: `Resources/Skins/` (там же `CREDITS.md` и `fetch-assets.sh`, воспроизводящий скачивание). Первая задача реализации — перенести их в `Sources/CodeCatApp/Skins/<набор>/`: SwiftPM требует, чтобы ресурсы лежали внутри каталога таргета, а нынешний `Resources/` лежит в корне и копируется вручную Makefile'ом. В `Package.swift` таргет `CodeCatApp` получает `resources: [.copy("Skins")]`.

В собранном `.app` ассеты лежат в `Contents/Resources/Skins` и покрыты подписью бандла. Доступ к ним — не через `Bundle.module`: сгенерированный им `resource_bundle_accessor.swift` падает с `fatalError`, если ни один из его путей не существует, а именно этот случай — пропавшие при сборке ассеты — и должен откатываться на нарисованного кота с алертом, а не крашить приложение при запуске. Вместо этого `SpriteSheetStore` перебирает вручную кандидатов пути — сперва `Bundle.main.resourceURL/Skins` (установленный `.app`), затем расположение ресурсного бандла SwiftPM рядом с исполняемым файлом (`swift run` и тому подобные бесструктурные запуски) — и возвращает `nil`, если не нашёл ни одного: `nil` здесь означает «откатиться на нарисованного кота и сообщить об этом», а не падение процесса.

**`make app` должен дополнительно копировать `.build/release/CodeCat_CodeCatApp.bundle` в `Contents/Resources/` и проверять результат:** после сборки цель убеждается, что бандл на месте и что в нём лежит каждый объявленный лист, иначе падает с ошибкой. Без этого облики работают под `swift run` и молча ломаются в установленном приложении — ровно тот класс дефекта, который в этом проекте уже дважды ловился только запуском собранного бандла, и который тест по `#filePath` (см. «Тестирование») поймать не может, потому что смотрит на исходники, а не на бандл.

Рядом с ассетами кладётся `Sources/CodeCatApp/Skins/CREDITS.md` с автором, лицензией и ссылкой по каждому набору, и оригинальные файлы лицензий из архивов — как есть, без переписывания.

**Про условие Elthen «нельзя раздавать сами ассеты».** Репозиторий локальный, без remote, поэтому сейчас файлы никуда не раздаются, а внутри собранного `.app` это обычное использование. Решение зафиксировано здесь и в `CREDITS.md`: **если репозиторий когда-нибудь станет публичным, лист Elthen из него удаляется**, а его место занимает `fetch-assets.sh`, который скачивает лист с itch.io на машину пользователя. У LuizMelo (CC0) и mxmaze (CC BY 4.0) такого ограничения нет.

## Интерфейс

В панели деталей (ширина 290 pt), ниже списка сессий и выше переключателей:

- **Сетка превью 4 колонки × 2 ряда** — восемь обликов помещаются целиком, без горизонтальной прокрутки. Прокрутка внутри всплывающей панели, которая закрывается по клику мимо, — способ промахнуться, а не выбрать. Превью ~34 pt: четыре штуки с отступами занимают ~160 pt из 290.
- Каждое превью проигрывает анимацию состояния «ждёт тебя» — то, ради чего маскот и существует. Это восемь анимаций одновременно, поэтому у превью fps ограничен четырьмя, и они существуют только пока панель открыта.
- Выбранный облик обведён рамкой. Тап переключает немедленно, панель не закрывается.
- Под сеткой — строка «Об ассетах», раскрывающая список: имя набора, автор, лицензия, ссылка на источник. Для CC BY 4.0 (mxmaze) это обязательство лицензии, для остальных — вежливость.

Выбор хранится в `UserDefaults` под ключом `mascotSkin`, по умолчанию `luizmelo-cat-1` (Рыжий). Ничего не меняется само у тех, кто уже пользуется приложением и уже выбрал спрайтовый облик; у тех, чей `UserDefaults` всё ещё хранит `"drawn"`, при следующем запуске это молча разрешится в Рыжего — тем же путём, что и любой другой неизвестный идентификатор.

## Обработка ошибок

- Лист не загрузился (файл потерян при сборке, битый PNG) → облик откатывается на облик по умолчанию, а на экране в этот момент кот рисуется аварийным нарисованным `CatView` (единственная причина, по которой этот код вообще остаётся в приложении), и показывается `NSAlert` по-русски: набор загрузить не удалось, выбран облик по умолчанию. Именно алерт, а не строка в панели: панель может быть закрыта, а в этом проекте действует правило «нет молчаливых отказов» — тот же приём, что у перехода к сессии (`AppState.presentJumpAlert`, включая вывод приложения вперёд, потому что CodeCat — accessory-приложение и его окно иначе не всплывёт). Показывается один раз за запуск. Маскот не исчезает никогда. Если даже облик по умолчанию не грузится, отката больше некуда: `skinID` присваивается то же самое значение, `.task(id: skin.id)` не перезапускается (id не изменился), и цикл не повторяется — просто остаётся аварийный `CatView`.
- Неизвестный идентификатор в `UserDefaults` → облик по умолчанию, молча: это не ошибка пользователя.
- Кадр вне листа (несовпадение объявленных кадров с реальным файлом) → ловится тестом на сборке, а не в рантайме (см. ниже).

## Тестирование

В `CodeCatCore`, на чистых данных:

- У каждого облика из реестра разрешены все пять состояний.
- Идентификаторы обликов уникальны и не меняются (тест фиксирует список — переименование сломает сохранённый выбор пользователя).
- Каждый облик, чья лицензия требует атрибуции, присутствует в списке credits; у каждого облика заполнены автор и ссылка на источник.
- Соответствие `AggregateStatus → AggregateStatusKey` покрывает все случаи, включая `.working(n)`/`.waiting(n)` с любым n.
- Ни у одной анимации нет пустого списка кадров и неположительного fps.
- Правило масштаба: на рамках 27×14, 18×12 и 16×16 даёт 4, 5 и 4; ширина после масштабирования нигде не превышает 120, высота нигде не превышает 64; вырожденная рамка (1×1, огромная) не даёт ноль или отрицательное число.

Тест на согласованность с файлами (в тестах приложения не выйдет — ресурсы лежат в таргете `CodeCatApp`, у которого тестов нет; значит лист проверяется тестом в `CodeCatCore` по пути к каталогу исходников, известному через `#filePath`): для каждого облика каждый объявленный файл существует, а максимальный объявленный индекс кадра меньше, чем `(ширина / frameSize) * (высота / frameSize)` реального PNG. Это тот тест, который ловит опечатку в таблице соответствий до запуска приложения. Он смотрит на исходники, поэтому не заменяет проверку бандла в `make app`.

Слой AppKit/SwiftUI (реальная отрисовка, превью, прокрутка) юнит-тестами не покрывается — установившаяся граница проекта. Проверяется рендером в PNG и запуском собранного бандла.

## За скобками

- Загрузка обликов пользователем со стороны.
- Покупные наборы (в отчёте есть вариант за $6) — решение по ним не принято и в эту работу не входит.
- Дорисовка недостающих состояний вручную в стиле каждого набора.
- Смена облика по расписанию, случайный облик, «кот дня».

## Что изменилось после вычитки

Спек был вычитан после того, как каждое утверждение сверили с самими файлами. Числа кадров, размеры листов и отсутствие `Itch` у `Cat-3` подтвердились; изменилось следующее:

1. **Правило масштаба переписано.** Прежнее `floor(96 / max(ширина, высота))` разводило облики по высоте вдвое (LuizMelo 42 pt против mxmaze 96 pt), потому что нормировало бо́льшую сторону, а коты LuizMelo широкие и низкие. Теперь нормировка по высоте с ограничением по ширине.
2. **Кадрирование стало одним на облик**, а не на анимацию: поанимационное подбрасывало бы кота при смене состояния (рамка спящего кота вдвое ниже рамки работающего).
3. **«Закончил» у mxmaze перенесён с (2,0) на (1,0):** весь нижний ряд листа нарисован с закрытыми глазами, и состояние читалось бы как сон.
4. **Ряд превью заменён сеткой 5×2** — девять превью по 36 pt не помещались в панель шириной 290 pt и требовали горизонтальной прокрутки внутри всплывающей панели.
5. **Добавлены подписи и идентификаторы обликов** — их в спеке не было, а `Cat-1…Cat-6` в файлах различаются только номером.
6. **`make app` теперь проверяет бандл ресурсов**, а не просто копирует его: тест по `#filePath` смотрит на исходники и этот класс дефекта не ловит.
7. **Ошибка загрузки листа стала алертом**, а не строкой в панели: панель может быть закрыта.
8. **Зафиксировано решение по условию Elthen** о нераспространении ассетов на случай, если репозиторий станет публичным.
9. **Проверено и оставлено как было:** сон у LuizMelo — склейка `Sleeping1`/`Sleeping2`, потому что `Laying` оказался переходом, а не петлёй.
10. **Доступ к ассетам переписан с `Bundle.module` на ручной перебор путей.** Сгенерированный `Bundle.module`-аксессор падает с `fatalError`, если ассеты пропали из бандла, — а именно на этот случай спек обещает откат на нарисованного кота с алертом. `SpriteSheetStore` теперь сам проверяет кандидатов (`Bundle.main.resourceURL/Skins`, затем путь ресурсного бандла SwiftPM) и возвращает `nil` вместо краша, отдавая обработку существующему коду отката.
11. **Нарисованный кот убран из списка выбора; обликов теперь восемь, а не девять.** Причина не в качестве спрайтов, а в назначении нарисованного кота: реальный крах на машине пользователя показал, что лист спрайтов действительно может пропасть из собранного `.app`, и в этот момент маскот обязан не исчезнуть. До этой правки такой откат совпадал с «выбираемым по умолчанию обликом» — одна и та же сущность играла две разные роли: обычный выбор пользователя и аварийный резерв на случай отказа. Это развязано: `CatView` остаётся в коде только как аварийная отрисовка (`MascotView` переключается на него, когда `SpriteSheetStore.load` возвращает `nil`), а обликом по умолчанию в `UserDefaults` и точкой отката при сбое стал `luizmelo-cat-1` (Рыжий) — тёплый, плотный по цвету кот, ближе всего по духу к прежнему нарисованному. Сетка превью соответственно стала 4×2 вместо 5×2.
