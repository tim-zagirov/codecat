# Остров: маскот в вырезе MacBook — дизайн-спецификация

Дата: 2026-08-31
Статус: на вычитке у пользователя
Предшествующие спеки: `2026-08-28-codecat-design.md` (MVP), `2026-08-30-session-jump-design.md` (переход к сессии), `2026-08-30-mascot-skins-design.md` (облики)

## Задача

Дать второй способ показывать маскота: чёрная плашка высотой строки меню, накрывающая вырез экрана и заходящая крыльями влево и вправо. В левом крыле — кот, в правом — счётчик сессий. Наведение открывает короткое меню, клик — полное. Оба меню на абсолютно чёрном фоне, чтобы шов с физическим вырезом был невидим.

Текущий плавающий кот никуда не девается: это второй режим отображения, переключаемый пользователем, а не замена.

## Что измерено до проектирования

Замеры сняты на целевой машине (MacBook Pro 16", встроенный дисплей) программой на AppKit, а не взяты из документации:

| Величина | Значение |
|---|---|
| `NSScreen.frame` | `(0, 0, 1728, 1117)` pt, `backingScaleFactor` 2 |
| `NSScreen.visibleFrame` | `(0, 0, 1728, 1083)` pt |
| `safeAreaInsets.top` (высота строки меню с вырезом) | **32 pt** |
| `auxiliaryTopLeftArea` | `(0, 1085, 771, 32)` |
| `auxiliaryTopRightArea` | `(956, 1085, 772, 32)` |
| Отсюда вырез | x ∈ [771, 956], **185 pt** шириной, y ∈ [1085, 1117] |
| `CGWindowLevelForKey(.mainMenuWindow)` | 24 |
| `CGWindowLevelForKey(.statusWindow)` | 25 |
| `CGWindowLevelForKey(.popUpMenuWindow)` | 101 |

Три следствия, которые определили дизайн:

- **Строка меню на экране с вырезом — 32 pt, а не 22 pt** (`NSStatusBar.system.thickness` возвращает 22 и здесь бесполезен). Высота острова = `safeAreaInsets.top`.
- **Остров должен лежать на уровне 26** — выше строки меню (24) и выше чужих статус-иконок (25). Раскрытые системные меню живут на 101, поэтому они рисуются поверх острова и не конфликтуют с ним.
- **Вырез шириной 185 pt центрирован**, крылья растут наружу от его краёв: правый край левого крыла = 771, левый край правого = 956.

## Решения, принятые с пользователем

1. Форма — **крылья вокруг выреза**: единая чёрная плашка высотой строки меню, накрывающая вырез и оба крыла. Не пилюля под вырезом.
2. Два уровня меню: **наведение — короткое** (только список сессий), **клик — полное** (сессии, облики, тумблеры, хуки).
3. Остров живёт **только на встроенном экране**. Нет выреза — нет острова; управление остаётся в иконке статус-бара.
4. В покое остров **виден всегда**, справа вместо числа тусклая точка. Плюс отдельная настройка «прятать остров, когда сессий нет» — по умолчанию выключена.

## Осознанный компромисс

Крылья физически перекрывают строку меню: слева — меню фронтового приложения, справа — статус-иконки, которые дорастают до выреза при их большом количестве. Клики в перекрытой зоне достаются острову, а не тому, что под ним. Это неустранимо в выбранной форме, поэтому крылья держатся минимально возможными: **72 pt** — ширина самого широкого спрайта (56 pt) плюс отступ с обеих сторон. Крылья одинаковы слева и справа (см. «Доработка по фидбеку»), поэтому остров занимает 329 pt строки меню. Замерено на целевой машине: слева до края меню фронтового приложения остаётся запас, справа до первой статус-иконки — около 120 pt.

## Модель — `CodeCatCore/IslandLayout.swift`

Чистая геометрия, без AppKit: на вход `CGRect`ы, на выход `CGRect`ы. Тестируется целиком, как `MascotLayout`.

```swift
public enum IslandLayout {
    /// Отступ от спрайта до края крыла с каждой стороны.
    public static let wingPadding: CGFloat = 8

    /// Экран с вырезом — единственный, на котором остров показывается.
    public static func hasNotch(safeAreaTop: CGFloat) -> Bool

    /// Вырез: то, что осталось от строки меню между двумя вспомогательными
    /// областями. `nil`, если areas отсутствуют (экран без выреза).
    public static func notchRect(screenFrame: CGRect,
                                 auxLeft: CGRect?, auxRight: CGRect?) -> CGRect?

    /// Вся чёрная плашка: вырез плюс два крыла.
    public static func islandFrame(notch: CGRect) -> CGRect

    /// Ширина крыла — одна и та же слева и справа.
    public static let wingWidth: CGFloat

    /// Выпадающее меню: верхняя кромка вплотную к низу острова, центр по вырезу,
    /// подрезано по краям экрана.
    public static func menuFrame(island: CGRect, height: CGFloat, screenFrame: CGRect) -> CGRect
}
```

Ширина крыла = ширина отрисованного спрайта + `2 * wingPadding`, то есть считается из облика, а не задаётся константой. Прямоугольников содержимого внутри острова в модели нет: `IslandView` раскладывает три известные ширины (левое крыло, вырез, правое крыло) обычным `HStack`, и вводить для этого вторую систему координат незачем.

## Масштаб спрайта в строке 32 pt

`SpriteScale.factor` сейчас жёстко нормирует к 64 pt высоты и 120 pt ширины (константы `targetHeight`/`maxWidth`). Для острова нужны другие числа, поэтому у функции появляются параметры с текущими значениями по умолчанию — плавающий кот не меняется ни на пиксель.

Для острова: `targetHeight = 32`, `maxWidth = 60`. Проверено по реальным рамкам непрозрачных пикселей из спеки обликов:

| Облик | Рамка, px | Множитель | На экране, pt | Левое крыло, pt |
|---|---|---|---|---|
| LuizMelo, большинство котов | 27×14 | ×2 | 54×28 | 70 |
| LuizMelo, `cat-5` | 27×16 | ×2 | 54×32 | 70 |
| LuizMelo, `cat-4` | 28×16 | ×2 | 56×32 | 72 |
| Elthen | 18×12 | ×2 | 36×24 | 52 |
| mxmaze | 16×16 | ×2 | 32×32 | 48 |

Рамки взяты из `SpriteScaleTests`, где они уже зафиксированы по реальным пикселям: шесть котов LuizMelo не делят одну рамку, `cat-4` и `cat-5` выше остальных на два пикселя.

Самые высокие облики (32 pt) заполняют строку меню целиком, без зазора сверху и снизу. Это принято сознательно: любой `targetHeight` ниже 32 роняет mxmaze до ×1. Если вплотную к кромке экрана окажется некрасиво — запасной ход — поднять высоту острова до `safeAreaInsets.top + 4`, тогда крылья уйдут на 4 pt ниже выреза, а зазор появится. Решается глазами на пункте 2 ручного чеклиста.

Все три дают **целочисленный ×2** — обязательное условие для пиксель-арта (`.interpolation(.none)`). `targetHeight` меньше 32 ломает mxmaze: 16×16 при 30 pt падает до ×1 и кот становится вдвое мельче остальных.

Множитель сегодня вычисляется один раз при загрузке и лежит в `LoadedSkin.scale`, а `SpriteMascotView` жёстко занимает канву `MascotLayout.canvasSize`. Оба места надо открыть, не меняя поведения по умолчанию:

- `LoadedSkin.drawingSize(targetHeight:maxWidth:)` — размер для произвольной нормировки, считаемый из уже измеренного `bounds`; текущее свойство `drawingSize` остаётся как вызов с параметрами по умолчанию;
- `SpriteMascotView` получает необязательный `drawingSize` и необязательный размер канвы. Не передали — всё как сейчас.

## Отрисовка — `CodeCatApp/IslandView.swift`

- Фон `Color.black`, непрозрачный. Скруглены только нижние углы (радиус 10 pt); верхние прямые — они упираются в кромку экрана.
- Слева `SpriteMascotView(loaded:status:sessionCount:)` с `showsBadge: false` и островным масштабом: бейдж здесь не нужен, число живёт в правом крыле.
- Справа: число сессий (`store.badgeCount`, 13 pt, semibold, белый) либо, когда считать нечего, серая точка 6 pt. Цвет числа повторяет логику бейджа: красный, когда агент ждёт пользователя, иначе белый.
- Пульсации бейджа в остров не переносим: 32 pt строки меню — не то место, где что-то должно дёргаться в поле зрения постоянно.

## Взаимодействие — `CodeCatApp/IslandController.swift`

Окно: `OverlayPanel` (существующий класс) на уровне 26, `collectionBehavior` как у кота (`.canJoinAllSpaces`, `.fullScreenAuxiliary`, `.ignoresCycle`), `acceptsMouseMovedEvents = true`.

Наведение ловится `NSTrackingArea` (`.mouseEnteredAndExited`, `.activeAlways`), а не SwiftUI-хавером: окно не должно активироваться и не должно перехватывать фокус.

Состояния меню:

| Из | Событие | В |
|---|---|---|
| закрыто | мышь вошла в остров | короткое меню |
| короткое | клик по острову | полное меню |
| короткое | мышь вне острова **и** вне меню дольше 0.3 с | закрыто |
| полное | клик мимо (`didResignKey`) | закрыто |
| полное | клик по острову | закрыто |
| любое | сессия открыта по клику (прыжок) | закрыто |

Короткое меню закрывается по уходу мыши, полное — только кликом мимо: в полном лежат тумблеры и выбор облика, и оно не должно исчезать, пока пользователь ведёт мышь к нужному переключателю.

Регион наведения — это **остров и меню вместе**: пока мышь в любом из двух окон, короткое меню живёт.

## Переиспользование панели деталей

`DetailsPanelView` распиливается на части, чтобы одно и то же содержимое рисовалось на двух фонах:

- `SessionListView` — список сессий с прыжком и курсором (вся текущая логика `sessionRow` переезжает сюда без изменений);
- `SettingsSectionView` — облики, тумблеры, кнопка установки хуков;
- `DetailsPanelView` остаётся композицией этих двух на материале — то, что видит плавающий кот сегодня;
- `IslandMenuView(level:)` — те же части на `Color.black`: `.short` показывает только `SessionListView`, `.full` — обе.

Фон становится параметром, а не переписывается. Плавающий режим обязан выглядеть после этой правки ровно так же, как до неё.

## Переключение режимов

```swift
public enum MascotDisplayMode: String { case floating, island }
```

- `AppState.displayMode` — `@Published`, в `UserDefaults` под ключом `mascotDisplayMode`, по умолчанию `.floating`. Существующая установка не меняет поведение сама по себе.
- `AppState.islandHidesWhenIdle` — `@Published`, ключ `islandHidesWhenIdle`, по умолчанию `false`.
- Оба контроллера реализуют протокол `MascotPresenting { func setVisible(_ visible: Bool) }`. `AppDelegate` держит активный, пересоздаёт при смене `displayMode` и уничтожает предыдущий.
- Переключатель кладётся в **два** места: сегмент «Кот / Остров» в панели рядом с обликами и пункт в меню статус-бара. Второе — аварийный выход: если остров окажется недоступен (встроенный экран отключён), кота не будет видно вообще, и вернуться в плавающий режим надо откуда-то ещё.

## Краевые случаи

- **Нет экрана с вырезом** (внешний монитор, закрытая крышка, Mac без выреза): остров не создаётся, `IslandController.setVisible(true)` ничего не показывает. Управление — в статус-баре.
- **Смена конфигурации дисплеев**: подписка на `NSApplication.didChangeScreenParametersNotification` пересчитывает геометрию и показывает/прячет остров.
- **Полноэкранный режим**: остров остаётся видимым (`.fullScreenAuxiliary`). На экране с вырезом полноэкранное окно по умолчанию лежит ниже выреза, и остров попадает в уже чёрную полосу.
- **`showMascot == false`**: остров скрыт наравне с плавающим котом — это общий тумблер видимости маскота.
- **Смена облика на лету**: ширина левого крыла пересчитывается, окно меняет размер; открытое меню переставляется под новую геометрию.

## Проверка

Юнит-тесты (`CodeCatCoreTests`):

- `IslandLayoutTests` — вырез из вспомогательных областей; отсутствие выреза даёт `nil`; крылья растут наружу от краёв выреза и не залезают внутрь; ширина крыла следует за спрайтом; меню прижато к низу острова и подрезано у края экрана; узкий экран не выталкивает меню за границу.
- `SpriteScaleTests` — параметризованные вызовы: три реальные рамки (27×14, 18×12, 16×16) при `targetHeight = 32, maxWidth = 60` дают ×2; вызов без параметров сохраняет прежний результат для плавающего кота.

Ручной чеклист в `docs/HANDOFF.md` — на то, что юнит-тестами не ловится:

1. Остров совпадает по высоте с вырезом, шов между чёрной плашкой и вырезом не виден на светлых обоях.
2. Кот анимируется, спрайт не мылится (пиксели квадратные), не обрезан сверху/снизу.
3. Наведение открывает короткое меню; уход мыши закрывает его; проход мышью через остров к меню не закрывает его на полпути.
4. Клик открывает полное меню; тумблеры и выбор облика в нём работают; клик мимо закрывает.
5. Клик по сессии прыгает в терминал и закрывает меню.
6. Переключение режимов в обе стороны: плавающий кот возвращается на своё сохранённое место, остров исчезает без остатка.
7. Плавающий режим после распила `DetailsPanelView` выглядит и ведёт себя как раньше.


## Доработка по фидбеку (2026-08-31, после первой живой проверки)

Пользователь посмотрел работающий остров и назвал четыре вещи. Три из них — следствия решений, принятых выше, поэтому спека правится, а не дополняется.

**Крылья стали одинаковыми.** Крыло по ширине спрайта (48–72 pt слева) против фиксированных 34 pt справа давало перекос: физический вырез тоже чёрный, поэтому глаз видит одно пятно, и его центр уезжал от центра экрана на 9.5 pt. Вдобавок слева плотный спрайт, справа тонкая цифра — вес тянул туда же. Теперь оба крыла по 72 pt, остров всегда 329 pt и всегда симметричен относительно выреза. Ширина не зависит от облика, поэтому переключение облика не меняет форму в строке меню.

Подогнать спрайты разных обликов друг к другу нельзя: в полосе 32 pt целочисленным остаётся единственный множитель ×2, и ширины фиксированы (32, 36, 54, 56 pt). Облики поуже просто получают больше воздуха вокруг кота.

**Счётчик получил капсулу.** Одиночная цифра рядом с плотным спрайтом читается как штрих, и правая сторона проваливается. Теперь там капсула высотой 20 pt (заливка белый 0.10) с точкой статуса 6 pt и числом 13 pt semibold. Точка цветом повторяет статусы в списке сессий один в один — точка на острове и точка в строке меню обязаны значить одно и то же. Подпись («1 сессия», «3 сессии») отвергнута: русское счётное слово склоняется по числу, и ширина капсулы прыгала бы при каждом изменении счёта. Когда сессий нет, капсулы нет — остаётся точка белый 0.35.

**Разрыв на стыке был следствием двух ширин.** Меню шириной 290 центрировалось по острову шириной 271 и торчало на 10 pt с каждой стороны, а нижние углы острова при этом оставались скруглёнными — в уступах проступали обои. Теперь ширину меню задаёт остров (`menuFrame` больше не принимает ширину снаружи, только высоту), а пока меню открыто, нижний радиус острова равен нулю: скругляет углы уже меню, и две чёрные формы дают один силуэт.

**Раскрытие морфится.** Пружина `response 0.28, dampingFraction 1.0` — без отскока: у кромки экрана перелёт за конечную высоту читается как брак, а не как живость. Едет маска по высоте от верхней кромки, не масштаб, иначе текст растягивался бы. Окно меню при этом не анимируется по кадрам: оно сразу выставляется в конечный размер, а пружина идёт внутри него. Цена — во время анимации (~280 мс) прямоугольник меню перехватывает клики на ещё не закрашенной площади.

Переход «короткое → полное» происходит в той же панели, а не через закрытие и открытие новой: иначе список сессий мигнул бы и пересобрался. Поэтому панель меню всегда создаётся с правом становиться key — у живого окна это право не меняется.

**Оформление вынесено в `MenuStyle`.** Список сессий, сетка обликов и тумблеры показываются на двух поверхностях с противоположными правилами: панель лежит на системном материале, где уместны `.secondary`/`.tertiary` и акцентный цвет, а меню острова — на чистом чёрном, где системная семантика врёт (на светлой теме `.secondary` выдаёт почти чёрный текст на чёрном). Стиль передаётся через `Environment` и задаёт уровни белого (1.0 / 0.62 / 0.38 / 0.16 / 0.12 / 0.08), раскладку строки сессии, размеры ячеек облика, разделители и цвет тумблеров. Пресет `.panel` воспроизводит прежний вид панели один в один — это условие, а не пожелание.

На острове цвет живёт только в точках статуса: ни текста, ни заливок цветом. Выбранный облик обводится белой рамкой, а не системным синим, потому что синий уже занят статусом «закончил»; по той же причине тумблеры белые.
