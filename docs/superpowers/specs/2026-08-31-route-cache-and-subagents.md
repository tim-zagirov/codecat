# Кэш маршрутов и пометка субагентской работы — дизайн-спецификация

Дата: 2026-08-31
Статус: утверждена пользователем
Предшествующие спеки: `2026-08-28-codecat-design.md` (MVP), `2026-08-30-session-jump-design.md` (переход к сессии)

## Задача

Две жалобы пользователя, у которых после разбора оказался общий корень и один сосед.

**1. «Клик по строке сессии не работает».** Проверено сквозь: хук определяет владельца верно
(`host_pid: 53631`, `/Applications/Claude.app`, `com.anthropic.claudefordesktop`), маршрут
строится верно, `NSRunningApplication.activate` возвращает `true` и выводит приложение вперёд.
Дефекта в переходе нет. Некликабельны оказались строки сессий, **запущенных до старта текущего
процесса CodeCat**: приложение держит сессии только в памяти, и после перезапуска знает о них
лишь от вотчера транскриптов — без `hostPID`, то есть без маршрута. В панели у таких строк
честная приписка «переход недоступен — сессия запущена до CodeCat». За одну рабочую сессию
CodeCat перезапускался многократно (каждая пересборка), поэтому в норме такими были почти все
строки.

**2. «Работает 2, а показывает 4».** Разобрано отдельно и починено раньше (`badgeCount`):
бейдж считал все известные сессии, включая завершённые, а цвет брал из агрегатного состояния.
После починки число и цвет считаются по одному множеству. Остаток расхождения — не дефект:
все четыре строки соответствовали сессиям, писавшим `tool_use` меньше минуты назад. Но одна
из них выглядела загадкой: строка `eily-ios` показывала «работает · думает», хотя в самой
сессии никто ничего не делал — работа шла **внутри субагента**.

Из той же диагностики: «длится N мин» у восстановленных вотчером строк врёт — отсчёт идёт от
момента, когда CodeCat их заметил, а не от начала сессии.

## Что проверено до проектирования

- Транскрипты субагентов лежат в `~/.claude/projects/<проект>/<session-id>/subagents/agent-<agentId>.jsonl`
  и **несут `sessionId` родительской сессии**. Отдельных сессий они не создают — гипотеза
  «CodeCat считает субагентов сессиями» проверена и **отвергнута**. Отличительный признак строки —
  поле `agentId`, которого в обычных транскриптах нет.
- **Восстановить маршрут вживую не выйдет.** Идея сопоставлять сессию с процессом через открытый
  файл транскрипта проверена: `lsof` не показывает транскрипт ни у одного из четырёх живых
  процессов `claude` — файл открывается на дозапись и закрывается. Значит маршрут надо помнить.
- Хуки исправны: сессия, запущенная после старта CodeCat, приписки «переход недоступен» не имеет.
- Файловый ввод-вывод в `CodeCatCore` уже есть (`CodeCatPaths`, `HooksInstaller`,
  `LidSleepController`), так что кэшу там место.

## Решения

### 1. Кэшируются маршруты, а не сессии

**Ключевое различие, и оно не косметическое.** Сохранять список сессий нельзя: после перезагрузки
мака в панели всплыли бы призраки давно умерших сессий, и CodeCat начал бы врать в обе стороны
сразу — показывать несуществующее и держать ассерцию сна ради него. Кэш маршрутов таким свойством
не обладает: **из файла сессии не создаются никогда**. Он только дополняет сессию, которая уже
появилась от живой активности.

```swift
/// Всё, что известно о том, где живёт сессия, плюс когда она началась.
public struct SessionRoute: Codable, Equatable, Sendable {
    public let hostPID: pid_t?
    public let hostBundlePath: String?
    public let hostBundleID: String?
    public let tty: String?
    public let startedAt: Date
    /// Когда запись последний раз обновлялась — по ней чистится файл.
    public let updatedAt: Date
}
```

- Хранилище: `~/Library/Application Support/CodeCat/routes.json`, рядом с сокетом.
  Путь объявляется в `CodeCatPaths`.
- Пишется, когда хук приносит поля маршрута, и когда сессия появляется впервые (ради `startedAt`).
- Читается один раз при запуске.
- `SessionEnd` удаляет запись: сессия закончилась, помнить её незачем.
- Записи старше **семи суток** отбрасываются при загрузке. Файл не должен расти вечно, а маршрут
  недельной давности заведомо мёртв.
- Запись атомарная (`.atomic`), битый или нечитаемый файл — пустой кэш и молчание: это не ошибка
  пользователя и чинить ему нечего.

**Устаревший PID не опасен и специально не проверяется при загрузке.** Он уже проверяется дважды
ниже по течению: `SessionRouter.route` требует `isProcessRunning(pid)`, а `SystemJumpExecutor.activate`
сверяет путь бандла у процесса с тем, для которого маршрут построен, — именно потому, что macOS
переиспользует PID'ы. Третья проверка на старте ничего бы не добавила, а на перезагруженной машине
дала бы ложную уверенность.

### 2. Работа субагента видна в панели

`TranscriptParser.parseLine` распознаёт строку субагента по наличию `agentId` и помечает активность.
Признак берётся из данных, а не из пути к файлу: путь — свойство того, как Claude Code раскладывает
файлы сегодня, а `agentId` — свойство самой записи.

```swift
public struct TranscriptActivity {
    // ...существующие поля...
    /// Активность пришла из транскрипта субагента: работает он, а не сама сессия.
    public let isSubagent: Bool
}
```

Строка в панели получает подпись вида «работает · **субагент** выполняет команду». Смысл, который
это несёт: в самой сессии никто ничего не печатает, работу ведёт подчинённый агент. Именно эта
неочевидность и породила вопрос «почему написано „думает“, если я туда не заходил».

На агрегатное состояние, бейдж и политику питания это **не влияет**: работа субагента — это работа
сессии, спать в это время маку нельзя.

## Обработка ошибок

- Кэш не читается / битый JSON → пустой кэш, приложение работает как сегодня. Молча: пользователю
  тут делать нечего.
- Кэш не пишется (нет прав, диск полон) → молча продолжаем. Потеря кэша ухудшает поведение ровно
  до нынешнего, а мешать работе из-за необязательного удобства нельзя.
- Запись без `startedAt` (файл от будущей/прошлой версии формата) → запись игнорируется целиком.

## Тестирование

В `CodeCatCore`, на чистых данных:

- Кэш: запись → чтение возвращает то же; неизвестный id → `nil`; `SessionEnd` удаляет запись;
  записи старше семи суток отбрасываются при загрузке, свежие остаются; битый JSON → пустой кэш,
  без исключения.
- Подстановка: сессия, пришедшая от вотчера без маршрута, получает `hostPID`/`bundlePath`/`tty`
  и `startedAt` из кэша; сессия, пришедшая с полями от хука, кэш **не** перезаписывает своими
  пустыми значениями; из кэша не создаётся ни одна сессия при отсутствии активности.
- Парсер: строка с `agentId` даёт `isSubagent == true`, обычная — `false`; `sessionId` в обоих
  случаях берётся из поля `sessionId` (у субагента это родительская сессия — проверить на реальном
  примере из архива).
- Подпись: активность субагента даёт в `activityDescription` пометку, обычная — нет.
- `anyWorking` и `aggregate` от `isSubagent` не зависят (тест фиксирует это явно).

Слой AppKit/SwiftUI не покрывается — установившаяся граница проекта.

## За скобками

- Восстановление маршрута для сессий, запущенных до самой первой установки CodeCat: их хук не видел
  никогда, помнить нечего.
- Отображение дерева субагентов (сколько их, чем заняты) — нужна только пометка.
- Исключение из счёта сессии, в окне которой сейчас находится пользователь: обсуждалось, решено
  не делать.
