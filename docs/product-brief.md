# CodeCat — бриф о продукте

Собран по коду репозитория на коммите `9f530db` (2026-08-31). Всё, чего в коде нет,
помечено «НЕ ЗНАЮ».

## 1. Суть

Меню-бар утилита для macOS, которая следит за локальными сессиями Claude Code,
не даёт маку уснуть, пока агенты работают, и показывает на экране котика-оверлея,
позой отражающего состояние работы.

**Для кого:** пользователи Claude Code на macOS, которые запускают агентов на
длинные задачи и уходят от машины.

**Боль, которую снимает** (сформулирована в спеке `docs/superpowers/specs/2026-08-28-codecat-design.md`):

> «Агент задал вопрос или ждёт разрешения, а пользователь не заметил — время
> простаивает. Вторая: мак засыпает и обрывает многочасовую работу агентов.»

## 2. Форма поставки

**Тип:** нативное macOS-приложение, меню-бар (`LSUIElement`, иконки в доке нет)
плюс плавающее borderless-окно маскота поверх всех окон и всех Spaces.
Внутри бандла — второй исполняемый файл `codecat-hook` (CLI, читает JSON со stdin).

**Как ставится сейчас — только из исходников:**

1. `make app` → собирает `dist/CodeCat.app` (release-сборка SwiftPM, копирование
   `Info.plist`, скриптов и ассетов обликов в бандл, `codesign --force -s -`,
   затем два guard'а: наличие `Contents/Resources/Skins` и прогон `SkinAssetsTests`
   против собранного бандла).
2. Перетащить `dist/CodeCat.app` в `/Applications`, запустить.
3. В меню котика — «Установить хуки Claude Code».
4. Опционально — «Режим закрытой крышки» (просит пароль администратора один раз).

Готового `.dmg`, релиза, Homebrew-формулы и установочной команды нет.
Git-remote у репозитория отсутствует — репозиторий локальный.

**Требования:**

- macOS 14+ (`platforms: [.macOS(.v14)]`, `LSMinimumSystemVersion 14.0`).
- Для сборки: Swift-тулчейн (`swift-tools-version: 5.9`; проверялось на Apple Swift 6.3).
- Установленный Claude Code (CLI и/или десктоп) — без него утилита бессмысленна.
- Для режима закрытой крышки — права администратора (правится `/etc/sudoers.d/codecat`
  и ставится LaunchDaemon `/Library/LaunchDaemons/com.codecat.sleepreset.plist`).
- Подпись ad-hoc (`codesign -s -`), не нотаризовано. После каждой пересборки macOS
  заново спросит разрешение на автоматизацию — это следствие смены подписи.

## 3. Стек

- **Язык:** Swift. UI — SwiftUI внутри AppKit-обвязки (`NSPanel`, `NSStatusItem`, `NSAlert`).
- **Системные фреймворки:** AppKit, SwiftUI, Combine, IOKit (power assertion),
  ServiceManagement (`SMAppService` — автозапуск при логине), Foundation/Dispatch,
  DistributedNotificationCenter (события блокировки экрана), `sysctl` для дерева
  процессов, AppleScript через `osascript`.
- **Внешние зависимости: ноль.** В `Package.swift` секции `dependencies` нет вообще.
- **Три таргета:** `CodeCatCore` (вся логика, без UI), `CodeCatApp` (приложение),
  `codecat-hook` (CLI-хук). Плюс тест-таргет `CodeCatCoreTests`.

**Размер кодовой базы:**

| | строк | файлов |
|---|---|---|
| `Sources/CodeCatCore` | 2 160 | 24 |
| `Sources/CodeCatApp` | 2 159 | 12 |
| `Sources/codecat-hook` | 32 | 1 |
| `Tests` | 2 722 | 20 |
| **Swift всего** | **7 073** | **57** |
| bash-скрипты | 92 | 3 |

Плюс 74 PNG спрайт-листов (ассеты обликов) и ~285 КБ проектной документации
(`docs/`: спеки, планы, HANDOFF, исследование ассетов).

## 4. Функции

### Реализовано

- **Трекинг всех локальных сессий Claude Code в реальном времени** — видно, сколько
  сессий идёт, в каком проекте и чем именно занят агент («редактирует api.ts»,
  «выполняет команду», «ищет по коду», «запустил субагента», «думает»).
- **Точный сигнал «агент ждёт тебя»** — через хуки Claude Code (`SessionStart`,
  `Stop`, `Notification`, `SessionEnd`), а не по угадыванию.
- **Мак не засыпает, пока агент работает** — IOKit power assertion, отпускается
  через grace-период 2 минуты после последней работы.
- **Автоматика вместо ручного тумблера** — в отличие от кофеин-утилит, удержание
  включается и снимается само по состоянию сессий; при заряде батареи ниже 15%
  удержание не берётся вовсе.
- **Котик на экране, читаемый боковым зрением** — спит / работает (с бейджем числа
  сессий) / машет лапой (бейдж красный) / доволен / прижал уши. Перетаскивается
  мышью, позиция запоминается между запусками, можно скрыть.
- **Иконка в меню-баре** дублирует состояние (SF Symbols) и открывает меню со
  списком сессий и тумблерами.
- **Панель деталей** по клику на котика: список сессий, «Пока тебя не было»,
  переключатель обликов, тумблеры.
- **Переход к сессии** — клик по строке сессии переключает туда, где она живёт:
  Terminal.app — ровно в её вкладку (по tty, через AppleScript), десктопный
  Claude — приложение вперёд. Строка без известного маршрута не кликается и
  объясняет почему.
- **Режим закрытой крышки** — закрыл макбук и ушёл, агенты доработали
  (`pmset -a disablesleep`, разовое sudoers-правило ровно на две команды).
- **Страховка от зависшего флага сна** — LaunchDaemon каждые 60 с снимает
  `disablesleep`, если процесса CodeCat нет (переживает crash, `kill -9`, Force Quit).
- **«Пока тебя не было»** — сводка событий, накопленных между блокировкой и
  разблокировкой экрана.
- **Девять обликов котика** — нарисованный SwiftUI-кот (по умолчанию) + восемь
  спрайтовых из трёх бесплатных наборов; сетка живых превью, выбор сохраняется.
  Строка «Об ассетах» с авторами и лицензиями (обязательство CC BY 4.0 у mxmaze).
- **Звуки** на переходы «ждёт тебя» и «готово» — по умолчанию выключены.
- **Автозапуск при логине** (`SMAppService`).
- **Установка хуков без разрушения чужих настроек** — merge в `~/.claude/settings.json`,
  идемпотентно, чужие хуки и все остальные ключи сохраняются; при нечитаемом файле
  установка отменяется с диалогом, а не переписывает настройки пустым документом.
- **Fallback без хуков** — если хуки не установлены, «ждёт тебя» определяется
  эвристикой по паузе в транскрипте (5 минут), с меньшей точностью.
- **Отказоустойчивость хука** — `codecat-hook` при любой ошибке молча выходит с
  кодом 0 и не может помешать работе Claude Code.

### Заявлено в спеке, но не реализовано

- **Текущее состояние питания в панели и меню-баре** — MVP-спек обещал («Текущее
  power-состояние всегда видно в панели и меню-баре»), в коде нет.
- **Настраиваемые grace-период и порог батареи** — спек называл их настройками,
  в коде это константы (120 с, 15%), UI для них нет.
- **Пункт меню «Удалить хуки»** — функция `HooksInstaller.remove` написана и покрыта
  тестами, но в меню её не выводят; удалять хуки можно только руками.
- **Тумблер «показывать котика» в панели деталей** — есть только в меню-баре.

### Реализовано, но ни разу не проверено вживую

- **Ветка iTerm2 перехода к сессии** — AppleScript написан, но iTerm2 на машине
  разработки не установлен, и скрипт даже не компилировался против его словаря.
- **Спрайтовые облики в живом приложении** — отрисованы и просмотрены только как
  PNG (45 сочетаний «облик × состояние»), в запущенном приложении их никто не видел.

## 5. Путь пользователя

Сейчас (без готового релиза) — 6 шагов от нуля до первого результата:

1. Установить Xcode / Swift-тулчейн (если ещё нет).
2. Склонировать репозиторий. *(Публичного адреса нет — см. «Активы».)*
3. `make app`.
4. Скопировать `dist/CodeCat.app` в `/Applications`, запустить. Котик появился —
   это уже первый видимый результат.
5. В меню — «Установить хуки Claude Code». Диалогов ОС на этом шаге нет,
   правится только `~/.claude/settings.json`.
6. Запустить обычную `claude`-сессию. Котик переходит в рабочую позу, мак
   перестаёт засыпать.

Полезный результат наступает на шаге 4–6. Аккаунтов заводить не нужно,
ключей не нужно, конфигов писать не нужно.

**Дополнительные шаги, каждый со своим системным диалогом:**

- Режим закрытой крышки — один раз пароль администратора.
- Первый переход к сессии в терминале — один раз разрешение на автоматизацию
  (Apple Events; не Accessibility и не Запись экрана). После пересборки приложения
  спросят заново.

**Стоимость для пользователя: 0 ₽/$.** Платных API-ключей, подписок и облачных
сервисов CodeCat не требует ни в каком виде. Предполагается, что у пользователя
уже есть доступ к Claude Code — стоимость самого Claude Code вне периметра
этого инструмента.

## 6. Приватность

**Наружу не уходит ничего.** В коде нет ни одного сетевого вызова: `URLSession`,
сокеты в интернет, HTTP-клиенты, SDK аналитики отсутствуют полностью
(проверено грепом по `Sources/`). Единственные `https://`-строки в коде — ссылки
на страницы авторов спрайтов itch.io, показываемые как текст атрибуции.

**Телеметрии нет.** Ни счётчиков, ни crash-репортинга, ни «анонимной статистики».

**Что читается локально:**

- `~/.claude/projects/**/*.jsonl` — транскрипты сессий, из них берутся только
  `sessionId`, `cwd`, `timestamp` и имя вызванного инструмента с именем файла.
  Содержимое переписки, промпты и код не разбираются и никуда не пишутся.
- `~/.claude/settings.json` — чтение и запись только собственных хуков.
- Дерево процессов через `sysctl` — чтобы понять, в каком приложении и терминале
  живёт сессия.

**Что пишется локально:**

- `~/Library/Application Support/CodeCat/codecat.sock` — unix-сокет, канал
  «хук → приложение». Локальный домен, наружу не смотрит.
- `UserDefaults` — тумблеры, позиция котика, выбранный облик.
- При включённом режиме крышки: `/etc/sudoers.d/codecat` (ровно две разрешённые
  команды `pmset -a disablesleep 0|1`) и LaunchDaemon-plist.

**Всё локально, весь код виден.** Отдельно стоит отметить: `codecat-hook`
встраивается в конвейер Claude Code и получает на stdin JSON события — он его
дополняет полями маршрута и шлёт в свой же локальный сокет, никуда больше.

## 7. Отличия

**Альтернативы.** Ниже — известные мне общедоступные инструменты; по коду
репозитория это не проверялось, сравнение нужно перепроверить перед публикацией.

*Не давать маку спать:*

- `caffeinate` — встроенная в macOS CLI-утилита.
- **Amphetamine** (Mac App Store), **KeepingYouAwake**, **Caffeinated** — тумблер
  или таймер в меню-баре.

*Наблюдение за Claude Code:* штатные хуки и `Notification` самого Claude Code
(они умеют дёрнуть системное уведомление или звук, но состояния не агрегируют);
инструменты вокруг Claude Code вроде `ccusage` считают расход токенов, а не
состояние сессий. Прямого аналога «маскот + агрегатный статус сессий + питание»
я не знаю — **НЕ ЗНАЮ, нужно проверить рынок отдельно.**

*Экранные питомцы:* RunCat (бегущий кот в меню-баре по загрузке CPU), Bongo Cat,
Desktop Goose — реагируют на систему или ни на что, но не на состояние агентов.

**Чем CodeCat объективно отличается — по коду:**

1. **Удержание от сна привязано к состоянию агентов, а не к тумблеру.**
   `PowerManager` берёт assertion, когда `store.anyWorking == true`, и отпускает
   через 120 с после конца работы. Кофеин-утилиты этого различить не могут — они
   не знают, работает ли кто-нибудь.
2. **Сигнал точный, а не эвристический.** Состояние приходит из хуков Claude Code
   (`Notification` = «ждёт тебя»), эвристика по паузе — только запасной путь.
3. **Есть режим закрытой крышки** — `pmset disablesleep` с узким sudoers-правилом
   и внешним демоном-страховкой. Обычные assertion-утилиты закрытую крышку не
   переживают.
4. **Переход к конкретной вкладке терминала.** Хук — потомок процесса `claude`,
   поэтому проходит по предкам, находит владеющий `.app` и tty, и AppleScript
   выбирает ровно ту вкладку. Ни у одной обёртки над `caffeinate` такого
   маршрута нет по построению.
5. **Ноль зависимостей и ноль сети.** Весь продукт — 7 тыс. строк Swift на
   системных фреймворках.
6. **Различает `working` и `waiting` в политике питания.** Сессия, ждущая
   человека, не считается работой для удержания от сна, но считается для показа
   в маскоте — два разных агрегата над одной моделью.

## 8. Зрелость

- **Версия:** `0.1.0` (`CFBundleShortVersionString`), `CFBundleVersion` = 1.
  Git-тегов нет.
- **Стадия: работающий MVP, ранняя альфа.** Приложение собрано, установлено в
  `/Applications` на машине автора и запущено; сквозная цепочка
  `codecat-hook → сокет → SessionStore → маскот` подтверждена скриншотами на
  реальном рабочем столе. Режим закрытой крышки, по записи в `docs/HANDOFF.md`,
  установлен и проверен на реальной машине (README ещё утверждает обратное —
  README в этой части устарел).
- **Тесты:** 239 тест-функций в 20 файлах, всё — `CodeCatCore`. UI-слой
  (`CodeCatApp`) тестами не покрыт. `make app` дополнительно проверяет, что
  ассеты обликов попали в подписанный бандл.
- **CI нет.** Каталога `.github/` не существует, никаких конфигов CI в репозитории нет.
- **Проверено на:** одной машине автора, macOS с Apple Swift 6.3, Terminal.app.
  На других версиях macOS, на Intel-маках и в iTerm2 не запускалось.

**Известные ограничения и незакрытые хвосты** (из `docs/HANDOFF.md`, ни одно не блокирующее):

- Состояние питания нигде не отображается.
- Grace-период и порог батареи зашиты константами.
- Нет пункта меню «Удалить хуки».
- Меню-бар перестраивается целиком на каждое событие сессии.
- `hooksInstalled` вычисляется только при запуске приложения.
- Звук повторяется при переходе `.waiting(1) → .waiting(2)`.
- Дублируется перевод `SessionStatus` в русские подписи между двумя файлами.
- Один общий таймаут на все параллельные переходы: зависший короткий переход не
  отмечается, пока идёт длинный.
- Диалог ошибки перехода поднимается поверх возможного системного диалога
  разрешения — проверить не удалось.
- После пересборки и переустановки приложения разрешение на автоматизацию
  спрашивается заново (следствие ad-hoc подписи, не баг).

**Ждёт ручной проверки человеком** (пункты 9–16 чек-листа в README): подсветка и
курсор на строке сессии, сам переход в Terminal.app и в десктопный Claude,
поведение при отказе в автоматизации, сетка обликов, переключение кликом,
сохранение выбора, раскрытие «Об ассетах».

**Лицензия: файла `LICENSE` в репозитории нет.** Юридически это «все права
защищены». **НЕ ЗНАЮ**, какую лицензию планируется поставить.

**Открыт ли исходник:** сейчас нет — git-remote отсутствует, репозиторий только
локальный. **Важное препятствие к открытию:** спрайты Elthen нельзя
распространять по условиям автора. В `Sources/CodeCatApp/Skins/CREDITS.md` уже
записан план: при публикации лист Elthen удаляется из репозитория, его место
занимает `fetch-assets.sh`, скачивающий файл с itch.io на машину пользователя.
У LuizMelo (CC0) и mxmaze (CC BY 4.0) таких ограничений нет; атрибуция mxmaze
обязательна и уже выводится в интерфейсе.

  затем ревьюер, потом широкое ревью всей ветки. Половина коммитов — `fix:` после
  ревью.

**Зачем это писалось** — прямая цитата из спеки (`2026-08-28-codecat-design.md`):

> «Главная боль, которую решаем: агент задал вопрос или ждёт разрешения, а
> пользователь не заметил — время простаивает. Вторая: мак засыпает и обрывает
> многочасовую работу агентов.»

Оттуда же — сценарии, ради которых сделан режим крышки:

> «поставил задачу, закрыл ноут, ушёл с раздачей интернета с телефона — мак
> доработал и сам уснул»

> «Кейс „заблокировал мак в коворкинге" работает именно так: блокировка ≠ сон,
> процессы продолжаются.»

Ещё один мотив читается в `docs/HANDOFF.md` — методологический. Проект явно
используется как полигон для дисциплины разработки с субагентами; уроки
записываются в HANDOFF отдельным разделом («финальное ревью всей ветки окупается
каждый раз», «измеряй, а не спорь о геометрии», «сообщение не имеет права
утверждать то, чего код не знает»).

   remote'а нет вообще.

   автоматизацию будет сбрасываться при каждом обновлении.
